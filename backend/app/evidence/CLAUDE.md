# backend/app/evidence/CLAUDE.md

Pure layer: parsers, plausibility rules, inverse-variance fusion. **No I/O, no LLM, no `httpx`.**
Bytes or dicts in, `Shot`s / `Flag`s / `FusedEstimate`s out (plan §5).

## Non-negotiables

- **The LLM never judges plausibility.** Every flag comes from a deterministic rule here; the model only phrases it.
- **No free text into the chat.** Tool output is numbers + `FlagCode` enums. Cap any string read from a CSV or
  screenshot to `^[\w %./°-]{0,32}$`. Never store raw uploads.
- All TrackMan data is synthetic (L6). The link importer (`trackman_fetch.py`, `trackman_report.py`) is cut: don't build it.

## Add a parser (`parsers/<name>.py`)

```python
def parse_<name>(raw: bytes | dict, *, club: str | None = None) -> list[Shot]:
    """Pure. Output uses the pack's shots.csv columns; convert to mph / yd / deg here."""
```

- Header aliases go in `parsers/aliases/<vendor>.json` (one file per launch monitor), never in a shared dict.
- TrackMan CSV: parse the units row; group by a `Club` column if present; empty cells stay empty.
  **Dynamic Lie is absolute** (≈ 58–66°): if values sit in 45–80°, `impact_toe_up_deg = dynamicLie − club_lie`
  (62° + built lie for Takomo test clubs, 62° for an own club) before S1, or S1 rejects every real shot.
- `parse_trackman_csv(raw, club=...)` (#30) returns `TrackmanCsv {shots, clubs, dropped_clubs, vendor, units_seen,
  dynamic_lie_absolute}`. Routes: `POST /imports/trackman-csv` (pending import) and the generic
  `POST /imports/{id}/confirm`, which appends the import's `parsed_shots_json` to `FittingState.shots` and bumps
  `evidence_version`. Samples: `fixtures/trackman/` (synthetic, regenerate with its `generate.py`).
- Ball-line (`parse_ball_line`): `BallLineEvidence {readings, mean, sd, n}`; + = line leans toward the toe,
  `lie_need = −mean`. It is fused with the chart, never an override. Copy says "readings", never "shots".

## v1 rules (#31)

- `plausibility/shots.py`: S1, S3, S7, S8, S10, S14, one function each (`V1_SHOT_RULES`); `check_shots(shots,
  import_id=, extra_rules=)` runs them per club group and maps `shot_index` back. S10 predicts carry from ball
  speed / launch / spin (`CARRY_FIT`, fitted on train); no ball data, no S10.
- `plausibility/golfer.py`: G2 → G1 → G3 (`check_profile`), G11 carry (`g11_carry_self_vs_measured`); flag `field`
  is the profile field name, so FIT's `_flag_factor` applies the σ effect. G2 only for values outside the hard bounds
  or both sexes' soft range. `plausibility/ball_line.py`: G15.
- `fuse.py`: `sigma_factor`, `usable_shots` (drops rejects, keeps S8), `shot_quality`, `merge_flags`.
  `session_flags.refresh(session)` re-runs the golfer rules into `session.flags` + `state.pending_flags`;
  the confirm route and `POST /flags/recheck` call it. V6 = imports stay `pending` until confirmed.
- `resolve.py`: the golfer's `outlier_review` answer (`keep` / `confirm_value` / `exclude`) via
  `POST /flags/resolve {action, codes, import_id?}`; marks flags `resolved`, sets or clears profile values, drops or
  converts (S10) confirmed shots. State shots carry `import_id` so a flag finds its shots.

## Screenshot extraction checks (`plausibility/extraction.py`, #34)

- `validate_extraction(session, *, second_read=None, shot_rules=(), club="own_7i", import_id=None) -> list[Flag]`
  runs V1 cell integrity, V2 unit labels, V3 (the caller's S rules mapped back to screen rows), V4 (S1 bounds with a
  decimal-slip suggestion, smash / face-to-path / total-vs-carry checksums, confidence < 0.8) and V5 (double read).
  Cell flags carry `shot_index = cell.row`, `field = cell.field`. `v1_schema_check(raw)` is for unparsed model output.
- V4's S1 bounds and S3 / S6 / S13 tolerances come from `thresholds.py`. The screenshot route passes the v1 S rules
  (plus W2 when on) as `shot_rules`.
- Round stats: `parsers/round_stats.py` (`parse_round_stats` → `score_bucket_from_score` via `app.pack`) and G13 in
  its own file, `plausibility/round_history.py`.

## Wave 2 rules (#33), gated by `EVIDENCE_WAVE2` (`evidence/settings.py`, default on)

- `shot_checks.py` is the only place that reads the W2 setting for shots: `run_shot_rules(shots, monitor=,
  import_id=)` (trackman-csv and confirm routes), `run_screenshot_rules(session)` (screenshot route) and
  `stored_monitor(report_json)` (so confirm uses the review's monitor).
- `plausibility/shots_w2.py`: S2, S5, S6, S9, S11, S12, S13 (`wave2_shot_rules(monitor)`) and S17 once per import.
  `shots.apply_rules` runs them after v1, each on the shots nothing rejected yet. Tolerance 1.6 only for known home
  radars (`RADAR_MONITORS`) and pack `home_radar` sessions; TrackMan, GCQuad, vision and unnamed monitors are 1.0.
  S5 never confirms inside 3 RMSE of its predictor and only confirms with the loose club-speed-only fit.
  S13 rejects only its field: `fuse.usable_shots` blanks `face_to_path_deg` (`FIELD_ONLY_REJECTS`).
  Not built: S15 (link importer, cut), S16 / S18 (no parser reads the hitting surface or normalisation mode).
- `fuse.shot_rejects(flags)` is the one definition of "this reject drops the shot" (unresolved, not field-only).
- `plausibility/golfer_w2.py`: G4-G10 (`wave2_golfer_flags`, in `session_flags.refresh`) and G12 / G14
  (`wave2_fit_flags`, in `session_flags.refresh_fit_flags`, called after the rescore by the confirm, recheck,
  and profile patch routes with FIT's own swing buckets).
- On by default: they raise no flags on the persona fixtures or profiles, so the demo flow is unchanged.
  `EVIDENCE_WAVE2=0` turns them off.

## Severities (σ effect in `fuse.py`)

| Severity | Effect |
|---|---|
| `reject` | excluded from every estimate |
| `downweight` | σ × 2 |
| `confirm` | pending at σ × 3; the assistant asks |
| `info` | shown only |
| `unit_suspect` | source excluded until confirmed |
